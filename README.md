# ImbalanceCalc

Розрахунок платежу за небаланси електричної енергії для учасника балансуючої
групи гарантованого покупця.

Користувач завантажує місячний файл ГП через веб-інтерфейс, дані
перераховуються за Порядком здійснення розрахунків БГ ГП (Додаток 2 до Типового
договору), після чого формується:

- **місячний підсумок** — платіж без ПДВ, ПДВ і всього з ПДВ;
- **розрахунок по добах** — обсяги, відхилення та платіж за кожну добу;
- **окремий аналіз діб**, платіж за які перевищує **10 000 грн** (поріг налаштовується);
- **порівняння з іншим місяцем**;
- **PDF-звіт**, який зберігається у папку `reports/` у корені проєкту.

Методика описана окремим самодостатнім документом:
[docs/METHODOLOGY.md](docs/METHODOLOGY.md) — його можна використати як
специфікацію в іншому проєкті.

## Встановлення

```bash
python -m venv venv
venv\Scripts\activate          # Windows
pip install -e ".[dev]"
```

## Запуск

Веб-інтерфейс:

```bash
streamlit run app.py
```

Сторінки:

| Сторінка | Що містить |
|---|---|
| **Розрахунок** (`app.py`) | завантаження файлу, місячний підсумок з ПДВ, розрахунок по добах, погодинна деталізація, вивантаження звіту |
| **Аналіз** (`pages/1_Аналіз.py`) | загальний аналіз (концентрація платежу, розподіл за годинами, карта «доба × година», найдорожчі години), аналіз по добах з розбором обраної доби, порівняння з іншим місяцем |

Консольний варіант:

```bash
imbalance-calc "data/input/62W... липень 2026.xlsx" --pdf
```

Тести:

```bash
pytest
```

Синтетичний зразок вхідного файлу (реальні дані в репозиторій не потрапляють):

```bash
python scripts/make_sample.py
```

Якщо покласти реальний файл ГП у `data/input/`, вмикається тест
`tests/test_control_example.py`, який звіряє підсумок з виставленим рахунком.

## Вхідні дані

Місячний файл гарантованого покупця (xlsx) з 15 аркушами однакового формату:
рядок 1 — заголовок (`Доба`, `Зона`, `1 год` … `24 год`), далі по рядку на добу.
Перелік аркушів і відповідність величинам методики — розділ 8
[docs/METHODOLOGY.md](docs/METHODOLOGY.md).

Файл містить і вихідні, і похідні величини, тому при завантаженні звіряються
контрольні співвідношення (наприклад, `Фактичне відхилення = Факт − Прогноз + ΔW`);
розбіжності показуються як зауваження, розрахунок при цьому не зупиняється.

## Параметри розрахунку

Задаються у бічній панелі UI (або прапорцями CLI), бо у файлі ГП їх немає:

| Параметр | Опис | За замовчуванням |
|---|---|---|
| `K_e` | допустиме відхилення для типу генерації ВДЕ, % | 5 |
| `α` | частка відшкодування вартості врегулювання, % | 100 |
| `K_im` | коефіцієнт ціни небалансу за Правилами ринку | 0,05 |
| ПДВ | ставка податку, % | 20 |
| поріг доби | сума, вище якої доба аналізується окремо, грн | 10 000 |

> Набір значень за замовчуванням звірений з виставленим рахунком за липень
> 2026: розрахунок дає 637 464,21 грн без ПДВ при контрольній сумі
> 637 464,21 грн (розбіжність 0,002 грн — округлення рахунку до копійок).
> При зміні редакції нормативних актів значення треба перевіряти повторно;
> найчутливіший параметр — `K_im`.

## Структура

```
app.py                       головна сторінка Streamlit
pages/1_Аналіз.py            сторінка аналізу
scripts/make_sample.py       генератор синтетичного вхідного файлу
src/imbalance_calc/
    config.py                параметри розрахунку та шляхи
    models.py                SettlementResult: підсумки, ПДВ, доби понад поріг
    exceptions.py            винятки пакета
    cli.py                   консольний інтерфейс
    dataio/
        schema.py            відповідність аркушів файлу величинам методики
        loaders.py           xlsx -> погодинна таблиця
        validators.py        контрольні співвідношення та повнота даних
    core/
        methodology.py       глави 1-3 Порядку: вартість, W^alpha, частка Учасника
        settlement.py        збірка результату, коригуючий платіж
        daily.py             добові підсумки та поріг 10 000 грн
    reporting/
        summary.py           таблиці, форматування, порівняння місяців
        pdf_report.py        PDF-звіт (reportlab + діаграма matplotlib)
        excel_report.py      вивантаження в xlsx
    ui/components.py         спільні елементи інтерфейсу
tests/                       54 тести: формули, завантаження, звіти, сторінки UI,
                             звірка з виставленим рахунком
data/input | output | samples
reports/                     сюди зберігаються PDF-звіти
docs/METHODOLOGY.md          опис методики
```

## Перевірка результату

Платіж за годину `CIEQ_p,t` завжди невід'ємний: це сума до сплати Учасником, а
не сальдо. Години, у яких відносне відхилення не перевищує `K_e`, не
тарифікуються взагалі, тому кількість «годин з платежем» зазвичай суттєво менша
за 744.
