# Що лишилося зробити

## Крок «Самоперевірка збірки» в CI падає за таймаутом

**Статус:** не розібрано. Випуски поки збираються локально
(`installer\build.ps1 -Clean -Installer`) і викладаються вручну; збірка й сам
застосунок справні, ламається лише крок перевірки в GitHub Actions.

### Що відбувається

У workflow «Випуск» крок «Самоперевірка збірки» щоразу падає з
`Самоперевірка не завершилася за 2 хвилини`, хоча сама перевірка успішна.
Останній прогін — [33859898857](https://github.com/IgorParf/ImbalanceCalc/actions/runs/33859898857),
тег `v0.1.2`:

```
09:48:18  крок стартував
09:48:20  Самоперевірка пройдена: 24 модулів, шрифт PDF, parquet, xlsx   (2,1 с)
09:50:18  throw "Самоперевірка не завершилася за 2 хвилини"              (рівно 120 с)
```

Тобто застосунок відпрацював за дві секунди й записав успіх у журнал, а
`WaitForExit(120000)` вичекав повний таймаут і не побачив завершення.

### Що вже пробували — і що з цього вийшло

| Спроба | Гіпотеза | Результат |
|---|---|---|
| `Start-Process -Wait -PassThru` | оболонка не чекає на віконний .exe | висіло до таймауту кроку |
| `os._exit(code)` замість звичайного виходу | недемонічні потоки після важких імпортів тримають процес | не допомогло |
| `$null = $check.Handle` перед очікуванням | `-PassThru` не кешує дескриптор, тому `WaitForExit` сліпий | не допомогло (цей прогін) |

Локально під Windows PowerShell 5.1 усе працює: `завершився: True, код: 0,
час: 6,2 с`. У CI оболонка — `pwsh 7`.

### Чого бракує для висновку

Досі не виміряно головного: **чи процес насправді завершується**. Обидві
гіпотези — «процес живий» і «оболонка не бачить виходу» — дають однакову
картину в журналі, і саме тому три спроби поспіль били мимо.

Наступний крок — не чергова здогадка, а вимірювання: опитувати таблицю
процесів ОС замість того, щоб покладатись на об'єкт від `Start-Process`.

```powershell
$proc = Start-Process ".\dist\ImbalanceCalc\ImbalanceCalc.exe" `
  -ArgumentList "--selfcheck" -PassThru
$deadline = (Get-Date).AddSeconds(120)
while ((Get-Date) -lt $deadline) {
  if (-not (Get-Process -Id $proc.Id -ErrorAction SilentlyContinue)) {
    Write-Host "Процес зник з таблиці процесів"
    break
  }
  Start-Sleep -Milliseconds 500
}
```

Якщо процес зникає — винна оболонка, і треба відмовитись від `WaitForExit`
на користь опитування плюс коду виходу, записаного самим застосунком у файл.
Якщо не зникає — винен застосунок, і `os._exit` до нього чомусь не доходить;
тоді варто перевірити, чи не породжує bootloader PyInstaller окремий процес.

Перевіряти зручно через `workflow_dispatch`, не створюючи нових тегів.

### Чому це не терміново

На випуски це не впливає: інсталятор збирається локально тим самим
`build.ps1`, з тією самою самоперевіркою, яка локально проходить. Ризик —
у тому, що CI зараз не є незалежною перевіркою збірки, тож покладатись на
нього не можна, доки крок не полагоджено.
