# Методика розрахунку частки вартості врегулювання небалансу БГ ГП

> Самодостатній опис алгоритму. Файл написаний так, щоб його можна було
> перенести в інший проєкт і реалізувати розрахунок з нуля, без решти цього
> репозиторію.
>

> гарантованого покупця — «Порядок здійснення розрахунків балансуючої групи
> гарантованого покупця» (зі змінами згідно з Постановою НКРЕКП № 2060 від

## 1. Терміни та позначення

| Позначення | Опис | Одиниці |
|---|---|---|
| `t` | розрахункова година | — |
| `e` | генеруюча одиниця | — |
| `p` | Учасник балансуючої групи | — |
| `GB` | балансуюча група гарантованого покупця (БГ ГП) | — |
| `W_e,t^F` | фактичний обсяг відпуску/відбору генеруючої одиниці | кВт·год* |
| `W_e,t^PR` | прогнозний обсяг (погодинний графік, наданий ГП) | кВт·год* |
| `ΔW_e,t` | обсяг невідпущеної е/е через команди ОСП на зменшення навантаження (додатне значення) | кВт·год* |
| `ΔS_e,t` | обсяг невідпущеної е/е через команди ОСП з операційної безпеки (додатне значення) | кВт·год* |
| `W_t^SUM` | сальдований обсяг небалансу БГ ГП **без** урахування команд ОСП | кВт·год* |
| `W_t^SUMΔ` | сальдований обсяг небалансу БГ ГП **з** урахуванням (додаванням) обсягів ΔW, ΔS | кВт·год* |
| `P_t^DAM` | ціна РДН у торговій зоні «ОЕС України» | грн/кВт·год* |
| `IMSP_t` | ціна небалансу електричної енергії у торговій зоні «ОЕС України» | грн/кВт·год* |
| `K^im` | коефіцієнт ціни небалансу (Правила ринку) | частка |
| `K_e` | допустиме відхилення для типу генерації ВДЕ (Закон «Про ринок електричної енергії») | % |
| `α_e` | частка відшкодування Гарантованому покупцю вартості врегулювання небалансу | % |
| `IEQ_t^GB` | обсяг небалансу електричної енергії Гарантованого покупця | кВт·год* |
| `CIEQ_p,t` | частка вартості врегулювання небалансу, що відшкодовується Учасником | грн |

\* У Порядку одиниці — кВт·год та грн/кВт·год. У місячних файлах ГП обсяги
подані в **МВт·год**, а ціни — в **грн/МВт·год**. Формули від цього не
змінюються: добуток «обсяг × ціна» дає гривні в обох випадках, головне —
не змішувати одиниці в межах одного розрахунку.

## 2. Обсяги небалансу

### 2.1. Відхилення Учасника (глава 1, пп. 1.1–1.2)

Без урахування команд ОСП:

```
W_p,t^S  = Σ_{e∈p} ( W_e,t^F − W_e,t^PR )
W_t^SUM  = Σ_{p∈GB} W_p,t^S
```

З урахуванням команд ОСП (обсяги невідпущеної енергії **додаються**, тобто
відхилення «очищується» від наслідків команд):

```
W_p,t^SΔ  = Σ_{e∈p} ( W_e,t^F − W_e,t^PR + ΔW_e,t + ΔS_e,t )
W_t^SUMΔ  = Σ_{p∈GB} W_p,t^SΔ
```

### 2.2. Розділення на «плюс» і «мінус» (глава 3)

Для кожного Учасника окремо виділяються від'ємні та додатні відхилення:

```
W_p,t^SN  = W_p,t^S   якщо W_p,t^S  < 0, інакше 0
W_p,t^SP  = W_p,t^S   якщо W_p,t^S  > 0, інакше 0
W_p,t^SNΔ = W_p,t^SΔ  якщо W_p,t^SΔ < 0, інакше 0
W_p,t^SPΔ = W_p,t^SΔ  якщо W_p,t^SΔ > 0, інакше 0
```

У розрахунку використовуються **суми по всій групі**: `Σ_{p∈GB} W_p,t^SN`
тощо — вони виступають знаменником при розподілі вартості між Учасниками.

---

## 3. Вартість небалансу групи (пп. 1.3, 1.4)

```
             ⎧ W_t^SUM · ( P_t^DAM − min(P_t^DAM; IMSP_t) · (1 − K^im) ),     якщо W_t^SUM > 0
CIEQ_t^SUM = ⎨ |W_t^SUM| · ( max(P_t^DAM; IMSP_t) · (1 + K^im) − P_t^DAM ),   якщо W_t^SUM < 0
             ⎩ 0,                                                             якщо W_t^SUM = 0
```

`CIEQ_t^SUMΔ` рахується тією самою формулою, але від `W_t^SUMΔ`.

Обидві гілки невід'ємні: при `W > 0` множник `P^DAM − min(P^DAM; IMSP)·(1−K^im) ≥ 0`,
при `W < 0` множник `max(P^DAM; IMSP)·(1+K^im) − P^DAM ≥ 0`.

---

## 4. Вибір сценарію (глава 2, п. 2.1)

Обсяги невідпущеної енергії враховуються лише тоді, коли це **здешевлює**
врегулювання небалансу групи:

```
якщо CIEQ_t^SUM ≤ CIEQ_t^SUMΔ  →  сценарій «SUM»:  беремо W_t^SUM,  Σ W^SN,  Σ W^SP
якщо CIEQ_t^SUM >  CIEQ_t^SUMΔ  →  сценарій «SUMΔ»: беремо W_t^SUMΔ, Σ W^SNΔ, Σ W^SPΔ
```

Вибір робиться **погодинно**, незалежно для кожної години.

---

## 5. Враховане відхилення Учасника (п. 3.1)

```
          ⎧ ( W_e,t^F − W_e,t^PR + ΔW_e,t + ΔS_e,t ) · α_e/100,
          ⎪     якщо W_e,t^PR ≠ 0 та |W_e,t^F − W_e,t^PR + ΔW_e,t + ΔS_e,t| / |W_e,t^PR| · 100 > K_e
W_e,t^α = ⎨ ( W_e,t^F + ΔW_e,t + ΔS_e,t ) · α_e/100,
          ⎪     якщо W_e,t^PR = 0
          ⎩ 0,  в іншому випадку

W_p,t^α = Σ_{e∈p} W_e,t^α
```

Три важливі деталі:

1. У чисельнику **завжди** використовується відхилення з дельтами
   (`W^F − W^PR + ΔW + ΔS`), незалежно від того, який сценарій обрано в п. 4.
2. `K_e` — «мертва зона»: якщо відносне відхилення не перевищує допустиме,
   година для Учасника не тарифікується взагалі (`W^α = 0`).
   Порівняння **строге** (`>`), тобто рівно `K_e` % — це ще нуль.
3. При `W^PR = 0` перевірка на `K_e` не застосовується (ділення на нуль),
   враховується весь фактичний обсяг.

---

## 6. Частка вартості, що відшкодовується Учасником (п. 3.2)

**Сценарій «SUM»** (`CIEQ_t^SUM ≤ CIEQ_t^SUMΔ`):

```
            ⎧ | W_p,t^α / Σ_{p∈GB} W_p,t^SN · W_t^SUM | · ( max(P_t^DAM; IMSP_t)·(1+K^im) − P_t^DAM ),
            ⎪      якщо W_t^SUM < 0 та W_p,t^α < 0 та IEQ_t^GB < 0
CIEQ_p,t =  ⎨ W_p,t^α / Σ_{p∈GB} W_p,t^SP · W_t^SUM · ( P_t^DAM − min(P_t^DAM; IMSP_t)·(1−K^im) ),
            ⎪      якщо W_t^SUM > 0 та W_p,t^α > 0 та IEQ_t^GB > 0
            ⎩ 0,   в іншому випадку
```

**Сценарій «SUMΔ»** (`CIEQ_t^SUM > CIEQ_t^SUMΔ`) — те саме, але з
`W_t^SUMΔ`, `Σ W_p,t^SNΔ`, `Σ W_p,t^SPΔ`.

Тобто Учасник платить лише тоді, коли **збігаються три знаки**: напрямок
небалансу групи, напрямок власного врахованого відхилення та напрямок
небалансу самого Гарантованого покупця. Якщо Учасник «відхилився в інший
бік», ніж група, — за цю годину він не платить (але й не отримує компенсації).

### За добу та за місяць

```
CIEQ_p,d = Σ_{t∈d} CIEQ_p,t          (за добу d)
CIEQ_p,m = Σ_{d∈m} Σ_{t∈d} CIEQ_p,t  (за розрахунковий місяць, п. 3.3)
```

`CIEQ` — це вартість **без ПДВ**. ПДВ (20 %) нараховується зверху на
підсумкову суму.

---

## 7. Коригуючий платіж (глава 4)

При отриманні оновлених сертифікованих даних комерційного обліку та/або
оновлених даних ОСП щодо ΔW/ΔS розрахунок повторюється за главами 1–3 на
оновлених даних, а сума коригуючого платежу — це **арифметична різниця**:

```
Коригування = CIEQ_p,m(оновлені дані) − CIEQ_p,m(попередні дані)
```

Заборгованість Учасника оплачується протягом трьох робочих днів з дня
отримання акта коригування; заборгованість ГП може бути врахована в інші
розрахункові періоди.

## 8. Вхідні дані: місячний файл ГП

Гарантований покупець надає Учаснику xlsx-файл (ім'я містить EIC-код
Учасника та місяць, напр. `62W663740852221O липень 2026.xlsx`). Структура —
**15 аркушів однакового формату**: рядок 1 — заголовок, далі 28–31 рядків
(по одному на добу), колонки: `Доба` (`ДД.ММ.РРРР`), `Зона` (`IPS`),
`1 год` … `24 год`.

| Аркуш | Величина | Рівень |
|---|---|---|
| `Остаточний прогноз` | `W_e,t^PR` | Учасник |
| `Фактичні обсяги` | `W_e,t^F` | Учасник |
| `ΔW` | `ΔW_e,t + ΔS_e,t` | Учасник |
| `Ціни небалансу` | `IMSP_t` | ринок |
| `Ціни на РДН` | `P_t^DAM` | ринок |
| `Фактичне відхилення` | `W_p,t^SΔ` (з дельтами) | Учасник |
| `W sn` | `Σ_{p∈GB} W_p,t^SNΔ` | група |
| `W sp` | `Σ_{p∈GB} W_p,t^SPΔ` | група |
| `Сальдовий обсяг небалансу` | `W_t^SUMΔ` | група |
| `Фактичне відхилення без дельт` | `W_p,t^S` | Учасник |
| `W sn без дельт` | `Σ_{p∈GB} W_p,t^SN` | група |
| `W sp без дельт` | `Σ_{p∈GB} W_p,t^SP` | група |
| `Сальдовий обсяг небалансу бе…` | `W_t^SUM` | група |
| `ΔΣW` | `Σ_{p∈GB} (ΔW + ΔS)` | група |
| `IEQ_GB` | `IEQ_t^GB` | ГП |

> **Увага до назв.** Аркуші **без** позначки «без дельт» містять величини
> **з урахуванням** ΔW/ΔS (тобто варіанти з індексом `Δ`), а аркуші з
> позначкою «без дельт» — базові величини `W^S`, `W^SUM`, `Σ W^SN`, `Σ W^SP`.
> Це протилежно до інтуїтивного прочитання, тому перевіряється арифметично:
> `Фактичне відхилення = Фактичне відхилення без дельт + ΔW`, а
> `Сальдовий обсяг небалансу = Сальдовий обсяг небалансу без дельт + ΔΣW`.
>
> Назва останнього аркуша обрізана Excel'ем до 31 символу
> (`Сальдовий обсяг небалансу бе...`), тому зіставляти аркуші треба за
> префіксом, а не за точним рядком.

Аркуш `ΔW` містить суму `ΔW + ΔS` — окремого аркуша для команд з операційної
безпеки у файлі немає.

### Контрольні співвідношення для валідації

```
Фактичне відхилення без дельт  = Фактичні обсяги − Остаточний прогноз
Фактичне відхилення            = Фактичне відхилення без дельт + ΔW
Сальдовий обсяг небалансу      = W sn + W sp
Сальдовий обсяг небалансу(бд)  = W sn без дельт + W sp без дельт
Сальдовий обсяг небалансу      = Сальдовий обсяг небалансу(бд) + ΔΣW
```

## 9. Параметри, яких немає у файлі

Їх треба задавати ззовні (конфіг або UI), бо вони залежать від типу
генерації, дати та чинної редакції нормативних актів:

| Параметр | Що це | Значення за замовчуванням |
|---|---|---|
| `K_e` | допустиме відхилення для типу ВДЕ, % | 5 (СЕС) |
| `α_e` | частка відшкодування вартості врегулювання, % | 100 |
| `K^im` | коефіцієнт ціни небалансу за Правилами ринку | **0,05** |
| ставка ПДВ | — | 20 % |

Цей набір значень звірений з виставленим рахунком (розділ 13). Найчутливіший
параметр — `K^im`: він входить множником у ціновий множник обох гілок формули
вартості, тому помилка в ньому зміщує підсумок пропорційно. Для липня 2026
різниця між `K^im = 0` і `K^im = 0,05` склала близько 6,8 % місячної суми.

При зміні редакції Правил ринку або перехідних положень Закону «Про ринок
електричної енергії» значення треба перевіряти повторно — найпростіше тим
самим способом, що описаний у розділі 12.

## 10. Псевдокод

```python
for t in hours:
    # 1. вартість небалансу групи в обох сценаріях
    cieq_sum  = group_cost(w_sum,   p_dam, imsp, k_im)
    cieq_sumd = group_cost(w_sum_d, p_dam, imsp, k_im)

    # 2. вибір сценарію (п. 2.1)
    if cieq_sum <= cieq_sumd:
        w_group, sum_sn, sum_sp = w_sum,   sum_w_sn,   sum_w_sp
    else:
        w_group, sum_sn, sum_sp = w_sum_d, sum_w_sn_d, sum_w_sp_d

    # 3. враховане відхилення Учасника (п. 3.1) — завжди від дельта-відхилення
    dev = w_f - w_pr + d_w              # = W^SΔ
    if w_pr == 0:
        w_alpha = (w_f + d_w) * alpha / 100
    elif abs(dev) / abs(w_pr) * 100 > k_e:
        w_alpha = dev * alpha / 100
    else:
        w_alpha = 0.0

    # 4. частка Учасника (п. 3.2)
    if w_group < 0 and w_alpha < 0 and ieq_gb < 0 and sum_sn != 0:
        cieq = abs(w_alpha / sum_sn * w_group) * (max(p_dam, imsp) * (1 + k_im) - p_dam)
    elif w_group > 0 and w_alpha > 0 and ieq_gb > 0 and sum_sp != 0:
        cieq = (w_alpha / sum_sp * w_group) * (p_dam - min(p_dam, imsp) * (1 - k_im))
    else:
        cieq = 0.0


def group_cost(w, p_dam, imsp, k_im):
    if w > 0:
        return w * (p_dam - min(p_dam, imsp) * (1 - k_im))
    if w < 0:
        return abs(w) * (max(p_dam, imsp) * (1 + k_im) - p_dam)
    return 0.0
```

## 11. Практичні зауваження щодо реалізації

* **Ділення на нуль.** `Σ W^SN` або `Σ W^SP` можуть дорівнювати нулю (у групі
  за цю годину немає відхилень відповідного знаку). Тоді знаки не збіжаться і
  гілка не спрацює, але захист у коді все одно потрібен.
* **Перехід на літній/зимовий час.** Файл ГП завжди має 24 колонки; доба на
  23/25 годин не відображається окремими колонками. Якщо потрібна прив'язка
  до реального часу — враховувати це на рівні timestamp, а не колонок.
* **Точність.** Обсяги у файлі — до 6 знаків, ціни — до 2. Розрахунок
  доцільно вести в `float64`, а округлювати лише при виводі (гроші — 2 знаки).
* **Знак результату.** `CIEQ_p,t ≥ 0` завжди: це сума до сплати Учасником, а
  не сальдо. Від'ємних значень бути не може — їх поява означає помилку у
  вхідних даних або в реалізації.
* **Перевірка порядку величин.** Для СЕС потужністю 10 МВт місячний
  `CIEQ_p,m` зазвичай вимірюється десятками–сотнями тисяч гривень; результат
  на кілька порядків більший/менший — привід перевірити одиниці (МВт·год
  проти кВт·год).

## 12. Обмеження ОСП: обсяг і тривалість

Показники суто інформативні — у платіж вони входять лише через саму величину
`ΔW` у формулах розділів 2 і 5. Але для звітності зазвичай потрібні два числа.

**Обмежений виробіток** береться прямо з файлу:

```
Обмежено виробіток за добу d = Σ_{t∈d} ΔW_t
Обмежено виробіток за місяць = Σ_{d∈m} Σ_{t∈d} ΔW_t
```

**Тривалість обмежень** у файлі відсутня: ГП подає обсяг невідпущеної енергії,
а не час дії команди ОСП. Її відновлюють як **еквівалентну тривалість** —
частку години, протягом якої станція фактично простоювала:

```
                ⎧ min( 1 ; ΔW_t / (W_t^F + ΔW_t) ),  якщо ΔW_t > 0 та W_t^F + ΔW_t > 0
Тривалість_t =  ⎨ 1,                                 якщо ΔW_t > 0 та W_t^F + ΔW_t ≤ 0
                ⎩ 0,                                 якщо ΔW_t = 0
```

де `W_t^F + ΔW_t` — потенційний виробіток години, тобто те, що станція видала б
без команди. Сума `Тривалість_t` по добі та по місяцю і дає значення у форматі
«год.хв».

Приклад (липень 2026, 05.07, година 9): `ΔW = 4,120` МВт·год при фактичних
`W^F = 1,3842` МВт·год. Потенціал `5,5042` МВт·год, частка
`4,120 / 5,5042 = 0,7485` год, тобто **45 хв** обмеження в цій годині.

За весь липень 2026: обмеження діяли у 49 розрахункових годинах на 9 добах,
еквівалентна тривалість — **33 год 51 хв**, обмежений виробіток —
**317,539 МВт·год**.

> Обмеження в межах години завжди часткові (у липні 2026 частка коливалась від
> 0,105 до 0,984, жодної повної години), тому кількість годин із `ΔW > 0` (49)
> і еквівалентна тривалість (33 год 51 хв) — різні величини. Перша відповідає
> на питання «скільки годин були зачеплені командами», друга — «скільки часу
> станція фактично не працювала».

## 13. Контрольний приклад

Реалізацію звірено з сумою, яку гарантований покупець фактично виставив
Учаснику за розрахунковий місяць.

**Вхідні дані:** місячний файл `62W663740852221O липень 2026.xlsx`
(СЕС 10 МВт, 31 доба × 24 години = 744 розрахункові години).

**Параметри:** `K_e = 5 %`, `α_e = 100 %`, `K^im = 0,05`.

| | грн |
|---|---|
| Виставлено за рахунком (без ПДВ) | 637 464,21 |
| Розраховано за цією методикою | 637 464,2078 |
| Розбіжність | 0,002 (округлення рахунку до копійок) |

Додатково: тарифікованих годин — 231 з 744; діб із платежем понад 10 000 грн —
9 з 31, на них припадає 90,1 % місячної суми.

### Як підібрати `K^im`, якщо він невідомий

`K^im` — єдиний параметр, який не читається з файлу і не задається договором
прямо. Якщо є хоча б один виставлений рахунок, коефіцієнт відновлюється
однозначно: залежність підсумку від `K^im` монотонна й майже лінійна, тому
достатньо порахувати суму для кількох значень і знайти те, що дає збіг.
Для липня 2026:

| `K^im` | Підсумок без ПДВ, грн |
|---|---|
| 0 | 596 625,35 |
| 0,01 | 604 793,12 |
| 0,02 | 612 960,89 |
| 0,03 | 621 128,66 |
| **0,05** | **637 464,21** ← збіг з рахунком |
| 0,10 | 678 281,55 |

Збіг до копійки на 744 годинах підтверджує не лише значення `K^im`, а й усі
інші рішення реалізації: зіставлення аркушів файлу з величинами методики
(розділ 8, зокрема прочитання «без дельт»), погодинний вибір сценарію
(розділ 4), строге порівняння з `K_e` (розділ 5) та умову збігу трьох знаків
у формулі частки Учасника (розділ 6). Помилка в будь-якому з цих пунктів дала
б розбіжність, яку не можна компенсувати підбором одного коефіцієнта.
