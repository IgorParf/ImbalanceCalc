# План: ImbalanceCalc як Windows-додаток

> Статус: **виконано** — застосунок збирається та встановлюється.
> Залишився лише необов'язковий етап 4 (підпис коду, автооновлення, CI).
>
> Складено 01.09.2026 на основі перевірки середовища (не припущень —
> див. розділ «Перевірені факти»).

---

## 1. Мета

Дати користувачеві звичайний Windows-додаток: ярлик у меню «Пуск», окреме
вікно замість браузера, без потреби встановлювати Python чи запускати
`streamlit run` з термінала.

---

## 2. Рекомендована архітектура

**Streamlit-рушій + нативне вікно pywebview + PyInstaller + інсталятор Inno Setup.**

Розрахункове ядро (`src/imbalance_calc`) уже не залежить від UI, тому
переписувати логіку не потрібно — змінюється лише шар запуску:

```
desktop/main.py  →  bootstrap.run() у фоновому потоці (Streamlit на 127.0.0.1)
                 →  pywebview відкриває це вікном
                 →  PyInstaller пакує все в теку
                 →  Inno Setup робить інсталятор
```

## 4. Що зламається при пакуванні

Обидва місця перевірені в коді, це не гіпотези.

### 4.1. Відносні шляхи сторінок — ✅ виправлено

[`app.py`](../app.py):

```python
st.Page("views/home.py", title="Головна", icon="⚡", default=True)
st.Page("views/analysis.py", title="Аналіз", icon="📊")
```

У запакованому додатку робочий каталог інший, сторінки не знайдуться.
**Зроблено:** шляхи будуються від `Path(__file__).resolve().parent`.

### 4.2. Каталог даних усередині встановленої програми — ✅ виправлено

Було в [`src/imbalance_calc/config.py`](../src/imbalance_calc/config.py):

```python
BASE_DIR = Path(__file__).resolve().parents[2]
```

У frozen-збірці це вказує всередину каталогу встановлення (доступний лише для
читання), тож `data/store/` і `reports/` писатися не будуть.

**Зроблено:** `resource_dir()` (ресурси програми, лише читання) та
`app_data_dir()` (дані користувача). У звичайному запуску — корінь проєкту,
у запакованому — `%LOCALAPPDATA%\ImbalanceCalc`. Через них проходять
`STORE_DIR`, `INPUT_DIR`, `OUTPUT_DIR`, `LOG_DIR`; `SAMPLES_DIR` лишається
поруч із програмою. Перевизначення: `IC_DATA_DIR`, `IC_STORE_DIR`.

`REPORTS_DIR` тепер вказує не в каталог проєкту, а в системну теку
«Завантаження» — див. розділ 4.3.

### 4.3. Тека звітів

Звіти зберігаються в системну теку «Завантаження», а перед записом
користувач може обрати іншу:

* шлях до «Завантажень» береться з `SHGetKnownFolderPath`
  (`FOLDERID_Downloads`), а не складається як `~/Downloads` — теку могли
  перенести на інший диск;
* у нативному вікні `ui/save_dialog.py` показує системний діалог
  «Зберегти як» через `create_file_dialog`; у pywebview 6 це
  `webview.FileDialog.SAVE` (старий `SAVE_DIALOG` уже позначено застарілим);
* у браузері нативний діалог неможливий, тому працює `st.download_button`;
* теку за замовчуванням перевизначає `IC_REPORTS_DIR`.

Каталог `reports/` із репозиторію прибрано — він більше не використовується.

### Етап 0 — обов'язково першим

Це єдиний реальний ризик усього плану. Python 3.14 вийшов недавно; PyInstaller
6.22 його підтримує, але зв'язка саме зі Streamlit не гарантована.

**Якщо спайк не злетить:** тримати окремий `venv312` **тільки для збірки**.
На розробку це не впливає — код сумісний з 3.12, а щоденна робота лишається
на основному `venv`.

### Етап 1 — `desktop/main.py`

```
знайти вільний порт
→ запустити bootstrap.run() у фоновому потоці з flag_options:
     server.headless = True
     server.address = "127.0.0.1"
     server.port = <порт>
     server.fileWatcherType = "none"
     global.developmentMode = False
     browser.gatherUsageStats = False
→ дочекатися, поки порт почне приймати з'єднання
→ webview.create_window("Небаланси", f"http://127.0.0.1:{port}", 1400×900)
→ webview.start()
→ закриття вікна завершує процес
```

Прив'язка саме до `127.0.0.1` важлива: `streamlit run` за замовчуванням
слухає всі інтерфейси й показує External URL — для десктопного додатку це
зайве відкриття назовні.

**Пастка, на яку наштовхнулися.** `bootstrap.run()` викликає
`signal.signal(SIGTERM, ...)`, а Python дозволяє це лише в головному потоці.
Головний потік зайнятий вікном pywebview, тож у фоновому потоці запуск падав з
`ValueError: signal only works in main thread of the main interpreter`.
Симптом підступний: вікно відкривається порожнім, а причина видно лише в лозі.

Рішення — `allow_signal_handlers_off_main_thread()` у `desktop/main.py`:
`signal.signal` обгортається так, щоб `ValueError` поза головним потоком
ігнорувався. Це безпечно, бо життєвим циклом застосунку керує закриття вікна,
а не сигнал; у головному потоці функція працює як зазвичай.

Альтернатива — піднімати Streamlit окремим процесом (`sys.executable` з
прапорцем). Надійніше в теорії, але подвоює пам'ять і ускладнює завершення,
тому обрано обгортку.

### Етап 2 — підводні камені пакування Streamlit

**Найпідступніша пастка: сторінки у збірці — це дані.**
`views/*.py` додаються як `datas`, тому PyInstaller **не аналізує їхніх
імпортів** і сам знаходить лише ті модулі пакета, які тягне `desktop/main.py`.
Наслідок: застосунок запускається, сервер піднімається, а на першій же
сторінці —

```
ModuleNotFoundError: No module named 'imbalance_calc.dataio'
```

Лікується `collect_submodules("imbalance_calc")` у `hiddenimports`. Але й тут
є пастка другого рівня: `collect_submodules()` виконується в тілі `.spec`
**раніше**, ніж `Analysis(pathex=[...])` додасть `src` у шляхи пошуку. Якщо не
додати `src` у `sys.path` вручну на початку `.spec`, функція мовчки поверне
порожній список, збірка пройде без жодного попередження — і застосунок
зламається так само. У `.spec` тепер стоїть перевірка, яка зупиняє збірку,
якщо зібрано менше 15 модулів.

Щоб такі пропуски не доводилося ловити руками, у застосунку є режим
`ImbalanceCalc.exe --selfcheck`: він імпортує всі модулі, потрібні сторінкам,
формує пробний PDF (перевіряючи заодно кириличний шрифт) і повертає код
виходу. `build.ps1` викликає його автоматично після збірки, а тест
`tests/test_packaging.py` стежить, щоб перелік модулів не відставав від
реальних імпортів сторінок.

Крім цього знадобиться:

* `--copy-metadata streamlit` — інакше падіння на
  `importlib.metadata.version("streamlit")`;
* `--collect-data streamlit` — фронтенд-асети (без них біла сторінка);
* `--collect-all pyarrow`;
* `--collect-data altair`;
* `--collect-data matplotlib` — **критично**: кириличний шрифт DejaVuSans для
  PDF береться саме з matplotlib, див.
  [`pdf_report.py`](../src/imbalance_calc/reporting/pdf_report.py), функція
  `_font_candidates()`. Без нього PDF-звіт не сформується;
* приховані імпорти: `streamlit.runtime.scriptrunner.magic_funcs`;
* дані: `views/`, `docs/METHODOLOGY.md`;
* виключити: `pytest`, `ruff`, `pip`, `tkinter`, `tests`.

**One-folder, не one-file.** One-file щоразу розпаковує ~300 МБ у temp: старт
20+ секунд і регулярні конфлікти з антивірусом.

### Етап 3 — інсталятор

Ставиться в `%LOCALAPPDATA%\Programs\ImbalanceCalc` — **без прав
адміністратора**, це прибирає UAC і при встановленні, і при оновленні.
Ярлики в «Пуск» та на робочому столі, штатний деінсталятор.

Файли: [`setup.iss`](../installer/setup.iss), збірка —
[`build.ps1 -Installer`](../installer/build.ps1) (сам знаходить `ISCC.exe`
у PATH та стандартних місцях). Версія береться з `imbalance_calc.__version__`
і передається в Inno Setup через `/DAppVersion=`, щоб не розходилася з
`pyproject.toml`.

**Ресурс версії для `.exe`.** Inno Setup показує версію у «Програмах та
компонентах» самостійно, але сам `.exe` без ресурсу версії має порожні
властивості файлу. Тому [`scripts/make_version_info.py`](../scripts/make_version_info.py)
генерує `installer/version_info.txt`, який підхоплює `.spec`.

Дві пастки, на які тут наступили:

1. **Порядок.** Ресурс має існувати *до* запуску PyInstaller. Інакше `.exe`
   збереться без даних версії, і жодної помилки не буде.
2. **Ідентифікатор мови.** У `StringTable` (`'040904B0'`) і у
   `VarStruct('Translation', [1033, 1200])` мова має збігатися: перші чотири
   шістнадцяткові цифри — це те саме число, що й перший елемент `Translation`.
   Спершу там стояли `040E` (угорська) і `1058` (українська) — Windows не
   знаходив таблицю і показував **порожні** властивості файлу, знову ж таки
   мовчки. Кодова сторінка `1200` — Unicode, тому самі рядки можуть бути
   українськими незалежно від ідентифікатора мови.

Обидві пастки зафіксовані тестами у
[`tests/test_version_info.py`](../tests/test_version_info.py).

**PowerShell і stderr нативних програм.** У Windows PowerShell 5.1 при
`$ErrorActionPreference = "Stop"` будь-який рядок, який зовнішня програма пише
у stderr, стає термінальною помилкою. PyInstaller і ISCC пишуть туди звичайні
INFO-повідомлення, через що збірка падала при нульовому коді повернення.
У `build.ps1` це обходить `Invoke-Native`: на час виклику рівень реакції
знижується, а успішність визначається за `$LASTEXITCODE`.

Без сертифіката підпису SmartScreen показуватиме попередження при першому
запуску. Сертифікат коштує приблизно $200–400/рік; для внутрішнього
інструменту зазвичай не купують, але користувача треба попередити заздалегідь.

## 6. Що додати саме в десктопній версії

* кнопка «Відкрити теку зі звітами» (`os.startfile`) — у браузерній версії
  шлях можна лише прочитати, відкрити теку неможливо;
* лог у `%LOCALAPPDATA%\ImbalanceCalc\logs` — без консолі помилки інакше
  не побачити;
* перенесення наявного `data/store/` при першому запуску встановленої версії;
* single-instance: якщо додаток уже запущено, активувати наявне вікно, а не
  піднімати другий сервер.
